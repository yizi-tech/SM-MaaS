# MASS 平台前端开发文档（Plans）

## 1. 项目背景

MASS 是一个 LLM API 网关 + 计费控制台平台（Go/Gin/GORM/MySQL/Redis 后端）。本前端项目为平台提供完整的 Web 控制台，分为**用户门户**与**管理后台**两个独立应用，通过后端 Gin 静态文件服务托管（`MASS_FRONTEND_DIR` 默认 `../frontend`，期望包含 `user/` 与 `admin/` 子目录）。

## 2. 技术选型

| 领域 | 选型 | 说明 |
|------|------|------|
| 框架 | React 18 + Vite 5 | 官方推荐构建工具，HMR 开发体验佳 |
| 语言 | TypeScript | 全量类型标注，与后端 DTO 对齐 |
| 组件库 | Ant Design 5 | 企业级组件库，覆盖表格/表单/仪表盘等场景 |
| 路由 | React Router v6 | 声明式路由 + 鉴权守卫 |
| HTTP | Axios | 统一拦截器、错误处理 |
| 图表 | Ant Design Charts / ECharts | 用量趋势、收入趋势 |
| 状态 | Zustand | 轻量全局状态（用户信息、额度快照） |
| 构建 | Vite（`base` 适配子路径部署） | 产物输出到 `user/`、`admin/` 目录 |

## 3. 目录结构

```
frontend/
├── user/                        # 用户门户构建产物（后端静态托管）
├── admin/                       # 管理后台构建产物
├── packages/
│   ├── shared/                  # 共享工具（请求封装、类型、常量、主题）
│   └── user-app/                # 用户门户源码（Vite app）
│   └── admin-app/               # 管理后台源码（Vite app）
```

> 构建时分别输出到 `frontend/user` 与 `frontend/admin`，由后端 `router.go` 的
> `r.Static("/user", ...)` / `r.Static("/admin", ...)` 提供服务。

## 5. 架构设计

### 5.1 请求封装（`shared/request.ts`）
- Axios 实例：`baseURL=/api/v1`，请求拦截器自动附加 `Authorization: Bearer <token>`。
- 响应统一处理 `{code, message, data}`；`code !== 0` 抛错并 `message` 提示。
- 401 统一跳转登录页并清理本地 Token。
- 分页响应 `{total, page, size, items}` 封装为 `PageResult<T>`。

### 5.2 鉴权与路由守卫
- Token 存 `localStorage`（key: `user_token` / `admin_token`）。
- 路由守卫：未登录访问受保护页 → 重定向登录页；已登录访问登录页 → 重定向首页。
- 管理端额外校验 `role === 'admin'`。

### 5.3 全局状态（Zustand）
- `useAuthStore`：token、user 信息、登录/登出。
- 用户门户额度快照（GUI 联动，支持毫秒级同步）：`/gui/sync`。

### 5.4 品牌主题
- 依据 `/site-config`（`site_name`/`site_logo`/`site_description` 等）动态渲染站点品牌。
- Ant Design 主题 token 统一配置主色（科技蓝/青），暗色菜单 + 亮色内容区。

## 8. 企业级视觉重设计（2026-08-23）

### 8.1 目标与约束

在不调整既有页面分区、路由、功能模块与核心交互流程的前提下，统一用户门户与管理后台的企业级视觉语言。设计方向为「可信赖的智能基础设施控制台」：用低饱和深色导航承载信息架构、以可信蓝作为关键操作色、以青色表达实时数据与连接语义，并将风险与财务状态使用固定语义色呈现。

### 8.2 视觉 Token

| 类别 | Token / 色值 | 适用范围 |
|------|-------------|----------|
| 品牌主色 | `#2563EB` | 主操作、选中态、链接 |
| 实时点缀 | `#06B6D4` | 实时同步、流量、品牌渐变 |
| 成功 / 警示 / 风险 | `#16A34A` / `#D97706` / `#DC2626` | 状态、额度预警、危险操作 |
| 内容底色 | `#F6F8FB` | 控制台页面背景 |
| 卡片与描边 | `#FFFFFF` / `#E4E9F1` | 数据卡、表格、表单容器 |
| 正文 / 辅助正文 | `#172033` / `#667085` | 信息层级 |
| 导航底色 | `#0B1220` | 侧栏与登录背景 |

Token 集中在 `packages/shared/src/theme.ts`，双端通过 Ant Design `ConfigProvider` 共同引用；全局 CSS 变量负责卡片、表格、工具栏、等宽数据值和响应式布局。

### 8.3 信息架构视觉化

- 用户端侧栏不增删功能，重组为「开发工作台 / 资源与计费 / 账户与支持」三组；当前项采用浅蓝选中面与左侧 3px 指示条。
- 管理端侧栏不增删功能，重组为「运营工作台 / 财务与风控 / 网关与商业化 / 服务运营」四组，提升运营扫描效率。
- 页面头部统一为 24px 标题、13px 辅助说明与右侧操作区；表格、卡片统一 12px 圆角、弱描边、低层级投影。
- 登录页采用暗色数据网格背景与轻量白色卡片，强化平台基础设施与可信赖的品牌感。

### 8.4 实施范围

1. 共享企业主题 Token、双端入口主题与全局样式规范。
2. 双端布局、导航分组、品牌区、顶栏与响应式视觉调整。
3. 用户总览和管理概览的数据卡片高度、数字表达与页面信息层级优化。
4. 保持所有 API 调用、字段、权限控制、路由和业务流程不变。

## 9. 联调与部署

- 本地开发：`vite dev`，通过 Vite 代理 `/api` → `http://127.0.0.1:8080`。
- 生产部署：构建产物放入 `frontend/user`、`frontend/admin`，后端设置 `MASS_FRONTEND_DIR=../frontend` 后由 Gin 直接托管。
- 后端启动需 MySQL + Redis，以及符合 `config.go` 校验要求的 `JWT_SECRET` / `DB_PASSWORD` 环境变量（开发可用 `MASS_ALLOW_INSECURE_DEFAULTS=true`）。
